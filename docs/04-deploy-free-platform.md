## Бесплатный деплой (платформы) — что реально бесплатно и какие ограничения

### Разница VPS vs Платформа (очень простыми словами)
- **VPS**: вы арендуете “свой сервер”. Плюсы: полный контроль, один домен, можно всё. Минусы: почти всегда платно и нужен админ (обновления, firewall, HTTPS, процессы).
- **Платформа (Render/Fly/Railway)**: вы загружаете код, а платформа сама запускает. Плюсы: проще, часто есть бесплатный тариф. Минусы: ограничения (сон, лимиты, иногда нет постоянного диска).

### Важно про бесплатные тарифы
На бесплатных тарифах часто бывает:
- “засыпание” сервиса после простоя (первый запрос потом медленнее)
- ограничения по CPU/RAM/трафику
- **нет гарантии постоянного диска** → SQLite-файл может потеряться при перезапуске

Поэтому для MVP есть 2 варианта:
1) **Самый простой**: терпим, что база может обнуляться (данные всё равно можно пересинхронизировать из Bitrix).  
2) **Правильнее**: подключаем бесплатный Postgres (Neon/Supabase) — но это следующий шаг, если захотите.

### Рекомендуемый бесплатный путь для MVP (чтобы cookies работали безопасно)
Лучше, чтобы **frontend и backend были на одном домене**. Мы уже сделали режим, где API в production **раздаёт frontend** (SPA).

Это означает: деплоим **один** Node-сервис, который:
- отдаёт сайт
- обслуживает `/auth`, `/me`, `/admin`

### Вариант A: Render (обычно самый понятный)
1) Залейте проект на GitHub (если ещё не залили)
2) Render → New → **Web Service**
3) Подключите репозиторий
4) Settings:
- Build Command:
```bash
npm install && npm run build -w @lk/web && npm run build -w @lk/api
```
- Start Command:
```bash
npm run start -w @lk/api
```
5) Environment variables (в Render UI):
- `NODE_ENV=production`
- `COOKIE_SECURE=true`
- `COOKIE_SAMESITE=strict`
- `JWT_ACCESS_SECRET=...` (длинная строка 30+ символов)
- `JWT_REFRESH_SECRET=...` (длинная строка 30+ символов)
- `DATABASE_URL=...` (для MVP можно оставить SQLite, но тогда нужно понимать, что диск может быть непостоянным)
- Bitrix параметры (если подключаем): `BITRIX_MODE=real`, `BITRIX_BASE_URL`, `BITRIX_WEBHOOK_PATH`, `BITRIX_REFERRER_FIELD`, `BITRIX_DEAL_REWARD_FIELD`

6) Deploy → дождаться запуска → открыть URL сервиса
